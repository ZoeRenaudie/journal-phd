## **🛠️ 2. Solutions techniques (par ordre de complexité)**

### **🔹 Option 1 : Tableur + Scripts Python (Solution la plus simple)**
**Pour qui ?** Si vous voulez une solution **rapide, sans base de données**, et que les utilisateurs sont à l’aise avec des tableurs (Excel/CSV).

#### **Étapes :**
1. **Créer un tableur** (Excel/CSV) avec des colonnes pour chaque propriété :
   - `ID` (ex: `ex:scarabattolo_remps`)
   - `Type` (ex: `crm:E22_Human-Made_Object`)
   - `Label` (ex: `"Scarabattolo (trompe-l'œil, Domenico Remps)"@fr`)
   - `Acteur` (ex: `ex:zoe_renaudie`)
   - `Source` (ex: `ex:rapport_conservation`)
   - `Date` (ex: `2017`)
   - `Proposition` (ex: `"L'objet X est de type Y"`)
   - `Degré de certitude` (ex: `"plausible"`, `"certain"`)

   
Exemple de tableur pour la saisie


   | ID                     | Type                          | Label                                      | Acteur          | Source                     | Date  | Proposition                          | Degré de certitude |
   |------------------------|-------------------------------|--------------------------------------------|-----------------|----------------------------|-------|------------------------------------------|--------------------|
   | ex:scarabattolo_remps  | crm:E22_Human-Made_Object     | "Scarabattolo (trompe-l'œil)"@fr          | ex:zoe_renaudie | ex:rapport_conservation   | 2017  | "ex:scarabattolo_remps est un E22"        | certain             |
   | ex:photo_1987_03       | crm:E38_Image                 | "Photo d'exposition"@fr                   | ex:conservateurA| ex:catalogue_entry_42      | 2020  | "La photo représente la coupe antique"   | plausible          |

2. **Écrire un script Python** pour convertir le CSV en RDF/Turtle :
   ```python
   import pandas as pd
   from rdflib import Graph, URIRef, Literal, Namespace
   from rdflib.namespace import RDF, RDFS, XSD

   # Charger le CSV
   df = pd.read_csv("donnees_ontologie.csv")

   # Initialiser le graphe RDF
   g = Graph()
   crm = Namespace("http://www.cidoc-crm.org/cidoc-crm/")
   crminf = Namespace("http://www.cidoc-crm.org/crminf/")
   ex = Namespace("http://example.org/")

   # Parcourir les lignes du CSV
   for _, row in df.iterrows():
       # Ajouter l'objet
       objet = URIRef(ex + row["ID"])
       g.add((objet, RDF.type, URIRef(crm + row["Type"])))
       g.add((objet, RDFS.label, Literal(row["Label"])))

       # Ajouter l'acteur
       acteur = URIRef(ex + row["Acteur"])
       g.add((acteur, RDF.type, crm.E21_Person))

       # Ajouter la source
       source = URIRef(ex + row["Source"])
       g.add((source, RDF.type, crm.E31_Document))

       # Ajouter la date
       date = URIRef(ex + row["ID"] + "_date")
       g.add((date, RDF.type, crm.E52_Time_Span))
       g.add((date, crm.P82a_begin_of_the_begin, Literal(f"{row['Date']}-01-01T00:00:00", datatype=XSD.dateTime)))
       g.add((date, crm.P82b_end_of_the_end, Literal(f"{row['Date']}-12-31T23:59:59", datatype=XSD.dateTime)))

       # Ajouter la proposition
       proposition = URIRef(ex + row["ID"] + "_prop")
       g.add((proposition, RDF.type, crminf.I4_Proposition_Set))
       g.add((proposition, crm.P129_is_about, objet))
       g.add((proposition, RDFS.label, Literal(row["Proposition"])))

       # Ajouter l'acte d'attribution
       acte = URIRef(ex + row["ID"] + "_act")
       g.add((acte, RDF.type, crm.E13_Attribute_Assignment))
       g.add((acte, crm.P14_carried_out_by, acteur))
       g.add((acte, crm.P17_used_specific_object, source))
       g.add((acte, crm.P4_has_time_span, date))
       g.add((acte, crm.P140_assigned_attribute_to, objet))

       # Ajouter la croyance (si degré de certitude)
       if pd.notna(row["Degré de certitude"]):
           croyance = URIRef(ex + row["ID"] + "_croyance")
           g.add((croyance, RDF.type, crminf.I12_Adopted_Belief))
           g.add((croyance, crminf.J4_that, proposition))
           valeur = URIRef(ex + row["Degré de certitude"])
           g.add((valeur, RDF.type, crminf.I6_Belief_Value))
           g.add((valeur, RDFS.label, Literal(row["Degré de certitude"])))
           g.add((croyance, crminf.J5_holds_to_be, valeur))

   # Exporter en Turtle
   g.serialize(destination="ontologie.ttl", format="turtle")
   ```

3. **Exécuter le script** :
   - Installez les dépendances : `pip install pandas rdflib`.
   - Lancez le script : `python script_conversion.py`.

4. **Résultat** :
   - Un fichier `ontologie.ttl` prêt à être importé dans un **triple store** (ex: [GraphDB](https://www.ontotext.com/products/graphdb/), [Fuseki](https://jena.apache.org/documentation/fuseki2/)).

---

#### **✅ Avantages :**
- **Simple** : Pas besoin de base de données ou d’interface complexe.
- **Flexible** : Modifiable avec Excel/Google Sheets.
- **Rapide** : Idéal pour des petits jeux de données.

#### **❌ Limites :**
- Pas d’interface utilisateur avancée.
- Risque d’erreurs de saisie dans le tableur.

### **🔹 Option 2 : Application Web avec Flask + RDFlib (Solution intermédiaire)**
**Pour qui ?** Si vous voulez une **interface web simple** pour saisir les données, sans base de données externe.

#### **Étapes :**
1. **Créer une application Flask** (Python) avec :
   - Un **formulaire HTML** pour saisir les objets, acteurs, propositions, etc.
   - Un **backend** qui génère le RDF/Turtle.

2. **Structure du projet** :
   ```
   mon_app/
   ├── app.py          # Code Flask
   ├── templates/
   │   └── index.html  # Formulaire de saisie
   ├── static/
   │   └── style.css   # CSS (optionnel)
   └── ontologie.ttl   # Fichier RDF généré
   ```

3. **Code de `app.py`** :
   ```python
   from flask import Flask, render_template, request, redirect, url_for
   from rdflib import Graph, URIRef, Literal, Namespace
   from rdflib.namespace import RDF, RDFS, XSD
   import os

   app = Flask(__name__)

   # Namespaces
   crm = Namespace("http://www.cidoc-crm.org/cidoc-crm/")
   crminf = Namespace("http://www.cidoc-crm.org/crminf/")
   ex = Namespace("http://example.org/")

   # Initialiser le graphe RDF
   g = Graph()

   @app.route("/", methods=["GET", "POST"])
   def index():
       if request.method == "POST":
           # Récupérer les données du formulaire
           objet_id = request.form["objet_id"]
           objet_type = request.form["objet_type"]
           objet_label = request.form["objet_label"]
           acteur = request.form["acteur"]
           source = request.form["source"]
           date = request.form["date"]
           proposition = request.form["proposition"]
           degre_certitude = request.form.get("degre_certitude", "")

           # Ajouter au graphe RDF
           objet = URIRef(ex + objet_id)
           g.add((objet, RDF.type, URIRef(crm + objet_type)))
           g.add((objet, RDFS.label, Literal(objet_label)))

           acteur_uri = URIRef(ex + acteur)
           g.add((acteur_uri, RDF.type, crm.E21_Person))

           source_uri = URIRef(ex + source)
           g.add((source_uri, RDF.type, crm.E31_Document))

           date_uri = URIRef(ex + objet_id + "_date")
           g.add((date_uri, RDF.type, crm.E52_Time_Span))
           g.add((date_uri, crm.P82a_begin_of_the_begin, Literal(f"{date}-01-01T00:00:00", datatype=XSD.dateTime)))
           g.add((date_uri, crm.P82b_end_of_the_end, Literal(f"{date}-12-31T23:59:59", datatype=XSD.dateTime)))

           proposition_uri = URIRef(ex + objet_id + "_prop")
           g.add((proposition_uri, RDF.type, crminf.I4_Proposition_Set))
           g.add((proposition_uri, crm.P129_is_about, objet))
           g.add((proposition_uri, RDFS.label, Literal(proposition)))

           acte_uri = URIRef(ex + objet_id + "_act")
           g.add((acte_uri, RDF.type, crm.E13_Attribute_Assignment))
           g.add((acte_uri, crm.P14_carried_out_by, acteur_uri))
           g.add((acte_uri, crm.P17_used_specific_object, source_uri))
           g.add((acte_uri, crm.P4_has_time_span, date_uri))
           g.add((acte_uri, crm.P140_assigned_attribute_to, objet))

           if degre_certitude:
               croyance_uri = URIRef(ex + objet_id + "_croyance")
               g.add((croyance_uri, RDF.type, crminf.I12_Adopted_Belief))
               g.add((croyance_uri, crminf.J4_that, proposition_uri))
               valeur_uri = URIRef(ex + degre_certitude)
               g.add((valeur_uri, RDF.type, crminf.I6_Belief_Value))
               g.add((valeur_uri, RDFS.label, Literal(degre_certitude)))
               g.add((croyance_uri, crminf.J5_holds_to_be, valeur_uri))

           # Sauvegarder le graphe
           g.serialize(destination="ontologie.ttl", format="turtle")
           return redirect(url_for("index"))

       return render_template("index.html")

   if __name__ == "__main__":
       app.run(debug=True)
   ```

4. **Code de `templates/index.html`** :

5. **Lancer l'application** :
   - Installez Flask : `pip install flask rdflib`.
   - Exécutez : `python app.py`.
   - Accédez à `http://localhost:5000` dans votre navigateur.

---

#### **✅ Avantages :**
- **Interface utilisateur** simple et accessible.
- **Génération automatique** du fichier RDF.
- **Extensible** (ajout de champs, validation, etc.).

#### **❌ Limites :**
- Pas de **base de données** : les données sont perdues après redémarrage (sauf si vous sauvegardez le fichier `ontologie.ttl`).
- Pas de **recherche ou visualisation** des données existantes.

### **🔹 Option 3 : Application Full-Stack avec Base de Données RDF (Solution avancée)**
**Pour qui ?** Si vous voulez une **solution complète** avec :
- **Stockage persistant** des données (base de données RDF).
- **Recherche et visualisation** des données.
- **Gestion des utilisateurs** (optionnel).

#### **Étapes :**
1. **Choisir un triple store** :
   - [GraphDB](https://www.ontotext.com/products/graphdb/) (recommandé, version gratuite disponible).
   - [Apache Jena Fuseki](https://jena.apache.org/documentation/fuseki2/) (open-source).
   - [Blazegraph](https://github.com/blazegraph/database) (open-source, léger).

2. **Créer une application web** (ex: avec **Flask + SPARQLWrapper**) :
   - **Frontend** : Formulaires pour la saisie (HTML/CSS/JS).
   - **Backend** : Requêtes SPARQL pour :
     - **Insérer** des données (`INSERT DATA`).
     - **Lire** des données (`SELECT`).
     - **Mettre à jour** des données (`DELETE` + `INSERT`).

3. **Exemple de code pour interagir avec GraphDB** :
   ```python
   from SPARQLWrapper import SPARQLWrapper, JSON
   from rdflib import Graph, URIRef, Literal, Namespace
   from rdflib.namespace import RDF, RDFS, XSD

   # Configuration de la connexion à GraphDB
   sparql = SPARQLWrapper("http://localhost:7200/repositories/mon_ontologie")

   # Exemple : Insérer une nouvelle proposition
   def inserer_proposition(objet_id, objet_type, objet_label, acteur, source, date, proposition, degre_certitude=None):
       query = f"""
       PREFIX crm: <http://www.cidoc-crm.org/cidoc-crm/>
       PREFIX crminf: <http://www.cidoc-crm.org/crminf/>
       PREFIX ex: <http://example.org/>

       INSERT DATA {{
           ex:{objet_id} a crm:{objet_type} ;
               rdfs:label "{objet_label}" .

           ex:{acteur} a crm:E21_Person .

           ex:{source} a crm:E31_Document .

           ex:{objet_id}_date a crm:E52_Time-Span ;
               crm:P82a_begin_of_the_begin "{date}-01-01T00:00:00"^^xsd:dateTime ;
               crm:P82b_end_of_the_end "{date}-12-31T23:59:59"^^xsd:dateTime .

           ex:{objet_id}_prop a crminf:I4_Proposition_Set ;
               crm:P129_is_about ex:{objet_id} ;
               rdfs:label "{proposition}" .

           ex:{objet_id}_act a crm:E13_Attribute_Assignment ;
               crm:P14_carried_out_by ex:{acteur} ;
               crm:P17_used_specific_object ex:{source} ;
               crm:P4_has_time-span ex:{objet_id}_date ;
               crm:P140_assigned_attribute_to ex:{objet_id} .
       """
       if degre_certitude:
           query += f"""
           ex:{objet_id}_croyance a crminf:I12_Adopted_Belief ;
               crminf:J4_that ex:{objet_id}_prop .

           ex:{degre_certitude} a crminf:I6_Belief_Value ;
               rdfs:label "{degre_certitude}" .

           ex:{objet_id}_croyance crminf:J5_holds_to_be ex:{degre_certitude} .
           """
       query += "}"
       sparql.setQuery(query)
       sparql.method = "POST"
       sparql.query()

   # Exemple : Lire les propositions
   def lire_propositions():
       query = """
       PREFIX crm: <http://www.cidoc-crm.org/cidoc-crm/>
       PREFIX crminf: <http://www.cidoc-crm.org/crminf/>
       PREFIX ex: <http://example.org/>

       SELECT ?objet ?label ?acteur ?source ?date ?proposition ?degre
       WHERE {
           ?objet a ?type ;
                  rdfs:label ?label .
           ?prop a crminf:I4_Proposition_Set ;
                 crm:P129_is_about ?objet ;
                 rdfs:label ?proposition .
           ?act a crm:E13_Attribute_Assignment ;
                crm:P14_carried_out_by ?acteur ;
                crm:P17_used_specific_object ?source ;
                crm:P4_has_time-span ?date ;
                crm:P140_assigned_attribute_to ?objet .
           ?date a crm:E52_Time-Span ;
                 crm:P82a_begin_of_the_begin ?start ;
                 crm:P82b_end_of_the_end ?end .
           OPTIONAL {
               ?croyance a crminf:I12_Adopted_Belief ;
                          crminf:J4_that ?prop ;
                          crminf:J5_holds_to_be ?valeur .
               ?valeur a crminf:I6_Belief_Value ;
                       rdfs:label ?degre .
           }
       }
       """
       sparql.setQuery(query)
       sparql.setReturnFormat(JSON)
       results = sparql.query().convert()
       return results["results"]["bindings"]
   ```

4. **Intégrer avec Flask** :
   - Utilisez les fonctions ci-dessus dans votre application Flask pour :
     - **Ajouter** des données via un formulaire.
     - **Afficher** les données existantes dans une table.

#### **✅ Avantages :**
- **Stockage persistant** : Les données sont sauvegardées dans le triple store.
- **Recherche avancée** : Utilisation de SPARQL pour interroger les données.
- **Évolutif** : Peut être étendu avec des fonctionnalités comme l’authentification, l’export, etc.

#### **❌ Limites :**
- **Complexité** : Nécessite de configurer un triple store (GraphDB/Fuseki).

## **📊 Comparatif des options**

| **Critère**               | **Tableur + Scripts** | **Flask + RDFlib**       | **Full-Stack + Triple Store** |
|---------------------------|-----------------------|--------------------------|-------------------------------|
| **Complexité**            | ⭐ (Très simple)       | ⭐⭐ (Intermédiaire)      | ⭐⭐⭐ (Avancé)                |
| **Coût**                  | Gratuit               | Gratuit                  | Gratuit (Fuseki) / Payant (GraphDB) |
| **Stockage**              | Fichier local         | Fichier local            | Base de données RDF          |
| **Interface utilisateur** | Tableur               | Web (basique)            | Web (avancée)                |
| **Recherche**             | Non                   | Non                      | Oui (SPARQL)                 |
| **Collaboration**         | Difficile             | Limitée                 | Oui                          |
| **Évolutivité**           | Faible                | Moyenne                  | Élevée                       |

---

---
## **🎯 Recommandation**
- **Pour un prototype rapide** : **Option 1 (Tableur + Scripts)**.
  → Idéal pour tester la modélisation et générer des données RDF sans développement complexe.

- **Pour une application simple avec interface** : **Option 2 (Flask + RDFlib)**.
  → Permet une saisie via un formulaire web, avec export en RDF.

- **Pour une solution professionnelle** : **Option 3 (Full-Stack + Triple Store)**.
  → Recommandé si vous prévoyez une utilisation intensive, avec recherche et collaboration.
